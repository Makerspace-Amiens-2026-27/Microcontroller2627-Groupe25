# 2026-11-26 : vérification de la toolchain et premier flashage

**Séance :** planifiée · **Durée :** 2 h

Tutoriel suivi : [Vérification de la toolchain](https://doc.makerspace-amiens.fr/workshops/microcontroleur/tutorials/toolchain-blink/?project=microcontroleur)
(atelier Microcontrôleurs, étape 3 sur 14, TD1).

## Fait

### Étape 1 : créer le projet PlatformIO

- Nouveau projet PlatformIO dans `project/firmware/pong/PONG ESP32/` :
  - **Board :** Seeed Studio XIAO ESP32S3 ;
  - **Framework :** Arduino.
- Ajout à la main de la ligne `monitor_speed` dans `platformio.ini` :

  ```ini
  [env:seeed_xiao_esp32s3]
  platform = espressif32
  board = seeed_xiao_esp32s3
  framework = arduino
  monitor_speed = 115200
  ```

- La ligne `#include <Arduino.h>` est conservée en tête de `src/main.cpp`.

### Étape 2 : brancher la carte

- Carte branchée avec un câble USB-C qui transporte les données (pas un câble de
  charge seule).
- Aucun driver à installer : la XIAO utilise l'USB natif de l'ESP32-S3, et le port
  COM apparaît dans le Gestionnaire de périphériques (« Périphérique série USB »).
- PlatformIO a trouvé le port tout seul : aucun `upload_port` n'est indiqué dans
  `platformio.ini`.

### Étape 3 : flasher le blink de base

Code téléversé (`src/main.cpp`) :

```cpp
#include <Arduino.h>

void setup() {
  pinMode(LED_BUILTIN, OUTPUT);
}

void loop() {
  digitalWrite(LED_BUILTIN, LOW);   // LOW allume la LED de la XIAO
  delay(500);
  digitalWrite(LED_BUILTIN, HIGH);  // HIGH l'éteint
  delay(500);
}
```

Compilation : `[SUCCESS]`.

| Mémoire | Utilisé | Disponible | Taux |
|---|---|---|---|
| RAM | 22 300 octets | 327 680 octets | 6,8 % |
| Flash | 272 495 octets | 3 342 336 octets | 8,2 % |

Puis téléversement avec le bouton **Upload** (flèche →) de la barre PlatformIO.

### Étape 4 : validation individuelle

## Analyse du firmware `pong`

À ce stade, le projet `pong` ne contient pas encore le jeu : c'est le programme
de vérification de la toolchain. Le même projet servira de base aux TD suivants.

### `platformio.ini`

| Ligne | Rôle |
|---|---|
| `[env:seeed_xiao_esp32s3]` | nom de l'environnement de compilation |
| `platform = espressif32` | outils Espressif : compilateur, esptool pour flasher |
| `board = seeed_xiao_esp32s3` | carte cible : ESP32-S3 à 240 MHz, 320 Ko de RAM, 8 Mo de Flash |
| `framework = arduino` | permet d'utiliser les fonctions Arduino (`pinMode`, `digitalWrite`, `delay`…) |
| `monitor_speed = 115200` | vitesse du moniteur série, à garder identique au `Serial.begin()` du code |

Le fichier est identique à celui du tutoriel. Aucune bibliothèque externe
(`lib_deps`) n'est déclarée : le blink n'en a pas besoin (« No dependencies »
dans le log de compilation).

### `src/main.cpp`

| Ligne | Code | Rôle |
|---|---|---|
| 1 | `#include <Arduino.h>` | déclare les fonctions Arduino. Dans un `.cpp`, elle n'est pas ajoutée automatiquement comme dans un `.ino` : sans elle, erreur « pinMode non déclaré » |
| 3-5 | `setup()` | exécutée **une seule fois** au démarrage : `pinMode(LED_BUILTIN, OUTPUT)` met la broche de la LED en sortie |
| 7-12 | `loop()` | exécutée **en boucle** sans fin |
| 8 | `digitalWrite(LED_BUILTIN, LOW)` | broche à 0 V : la LED **s'allume** |
| 9 | `delay(500)` | attente de 500 ms |
| 10 | `digitalWrite(LED_BUILTIN, HIGH)` | broche à 3,3 V : la LED **s'éteint** |
| 11 | `delay(500)` | attente de 500 ms |

`LED_BUILTIN` vaut **21** pour cette carte (défini dans le fichier de la carte
XIAO ESP32S3 du framework) : c'est la LED orange à côté du connecteur USB-C. La
LED rouge voisine indique la charge de la batterie et ne se pilote pas.

### Chronogramme

```text
temps (ms)  0         500       1000      1500      2000
GPIO21      |___LOW___|‾‾HIGH‾‾‾|___LOW___|‾‾HIGH‾‾‾|
LED orange  | allumée | éteinte | allumée | éteinte |
```

- Période : 500 ms allumée + 500 ms éteinte = **1 s**, soit une fréquence de
  **1 Hz**.
- Rapport cyclique : **50 %** (allumée la moitié du temps).

### Pourquoi LOW allume la LED (logique inversée)

La LED orange est câblée entre le **3,3 V** et la broche GPIO21 (avec sa
résistance), et non entre la broche et la masse :

- broche à **LOW** (0 V) : il y a 3,3 V aux bornes de la LED et de sa résistance,
  le courant passe, la LED s'allume ;
- broche à **HIGH** (3,3 V) : même tension des deux côtés, aucun courant, la LED
  est éteinte.

On dit que la LED est « active à l'état bas ». Une LED externe câblée entre une
broche et GND (montage du bonus) fonctionne à l'inverse : HIGH l'allume.

### Comparaison avec le projet `test blink` (séance du 24/11)

| | `test blink` (24/11) | `pong` (26/11) |
|---|---|---|
| Ordre dans `loop()` | HIGH puis LOW | LOW puis HIGH |
| Délai | 1000 ms | 500 ms |
| Fréquence | 0,5 Hz | **1 Hz** (demandé par le TD) |
| `lib_deps` | AccelStepper, ArduinoJson | aucune |
| Résultat | compilé seulement | compilé **et** téléversé |
| RAM / Flash | 22 300 / 272 495 octets | 22 300 / 272 495 octets |

Les deux programmes occupent exactement la même mémoire, alors que `test blink`
déclare deux bibliothèques. PlatformIO ne compile une bibliothèque que si le code
l'inclut avec `#include` : une bibliothèque déclarée mais jamais utilisée ne prend
donc aucune place dans le firmware.

### Limites du code actuel

- `delay()` est **bloquant** : pendant les 500 ms, le microcontrôleur ne fait rien
  d'autre. Pour le Pong, il faudra lire les boutons et le joystick pendant que la
  balle bouge : il faudra passer à une temporisation avec `millis()`, qui ne bloque
  pas la boucle.
- Le nom du dossier `PONG ESP32` contient une espace (le tutoriel propose
  `pong-esp32`). Cela fonctionne, mais les espaces dans les chemins peuvent poser
  problème avec certains outils en ligne de commande.

## Pourquoi

- **Valider la toolchain avant la suite :** si le blink compile, se téléverse et
  fait clignoter la LED, alors toute la chaîne fonctionne (PlatformIO, compilateur,
  configuration de la carte, câble, port USB). Un problème plus tard viendra du
  code ou du câblage, pas de l'installation.
- **Nouveau projet plutôt que `test blink` :** `test blink` contenait les
  bibliothèques de l'exemple d'installation (AccelStepper, ArduinoJson), qui ne
  servent pas à la console. Le projet `pong` part d'un `platformio.ini` propre,
  conforme au tutoriel, et sera réutilisé aux TD suivants.
- **1 Hz :** c'est la fréquence demandée par le TD. Elle est assez lente pour
  voir clairement chaque changement d'état à l'œil nu et dans la vidéo.
